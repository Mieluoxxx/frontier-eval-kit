三个 harness 怎么公平地跑 FrontierHarness Eval？

长图

答

结论

官方给 62 道题各配了一个 Linux 镜像。你们共用 Harbor 调度器，每次让一个 harness 进入这道题的全新容器，最后由同一套程序判分。1

  1. 题目会给一份真实的初始状态，例如带未合并提交的 Git 仓库。2
  2. 17 道题还配有独立判分镜像；其余 45 道由 Harbor 在任务环境中运行测试。3
  3. 官方每题独立跑 4 次。一个模型配三个 harness，共计 744 次计分尝试。4

适用于v1.1.0本地 Docker 横评单模型

1

一次尝试里发生了什么？

图的结构
  • 取题包 load
  • 开任务容器 start
  • Harness 做题 run
  • 程序验收 verify
  • 保存结果 save
  • load → start · 镜像与资源
  • run → verify · 文件或服务
  • start → run · 题面
  • verify → save · 得分

instruction.md 是考生读到的题面。task.toml 指定镜像、CPU、内存及超时。题包也提供测试脚本和参考解法。oracle 会执行参考解法，适合验收环境，无需调用模型。4

以 Git 题为例，判分程序读取站点的两个文件，分别核对内容。写一段操作说明交卷，文件本身不会变，测试就不会通过。2

真题要求交付什么？

题目接手时是什么样做完要交什么
Git 恢复用户切回 master，发现个人网站的改动消失了找回改动并合回主分支。2
日志汇总目录里有按日期和来源命名的日志按题面给定日期，统计五个时间段的三类事件，写成 CSV。5
C 与 Python已知两种语言的运行方式和目标路径同一份源文件既能用 Python 执行，也能用 GCC 编译，两种方式都输出斐波那契数。6
Nginx 配置镜像预置了 curl，安装 Nginx 是题目要求启动监听 8080 的服务，配置访问日志、限流及自定义 404。7
数据库恢复/app 里有带预写日志的存储引擎修复恢复逻辑，处理日志缺口和重复序号，保留约定接口。判分端单独启动。8

哪些工具该装在哪里？

位置准备内容
宿主机可用的 Docker Engine 和 Buildx。两边约定同一种任务架构；已核实 Git 题的预构建镜像是 linux/amd64。比较耗时时最好共用同一台原生 Linux 机器。
调度容器随包的 Dockerfile 固定了 Python 3.14 系列、uv、上游 eval 提交、Harbor 0.24.0、Docker CLI、Compose 和 Buildx。使用本地 Docker 后端。
任务容器按题包启动镜像，保留原始文件、工具和工作目录。Nginx 题若统一预装 Nginx，就替考生做掉了第一步。7
判分容器17 道题指定独立镜像。逐题镜像清单中的 separate_verifier_image 给出了镜像地址。3

官方排行榜使用 Runta 和 Baseten。它给每次尝试分配 32 GB 磁盘，各题使用 1 至 4 vCPU、2 至 8 GB 内存，作答时间从 15 分钟到 8 小时。本地 Docker 适合三方横比；本地磁盘配额还要看 Docker 存储后端。4

三个 harness 各怎么接？

参赛者接入约定
原版 Pi采用榜单同版 pi 1.4.0，由 Harbor 在新容器中安装。使用干净配置，不挂个人 Pi 目录，不配置 MCP、skills 或会注入扩展的 max_turns。9
MyGo-Bot准备与任务架构匹配的 Linux 可执行文件及运行库。适配脚本在题目工作目录启动 daemon，把题面发到新会话，等它完成，再让 Harbor 判分。上一次构建的是 macOS arm64 版本。
朋友的 harness固定发布版或提交。若已有单次命令行入口，可用 CommandAgent 上传产物，从 INSTRUCTION_FILE 读取题面，等任务完成后退出。10

自写适配器提供安装与运行命令。默认 CommandAgent 收集标准输出和错误，但没有解析 token 用量；要比花费，可统一取模型网关的 usage 记录。10
